At a glance

The paper in four results.

What if a voice agent could be trained in speech, not only scored in it? SpeechGym puts both sides of the call in native audio, on two local open models, so the agent learns by reinforcement learning end to end.

Finding 01

Speech breaks hearing, not reasoning.

The agent picks the right tool and the right slot, then fills it with a value it misheard.

 Finding 02

The obstacle is sparsity, not signal.

A reward for every tool call keeps nearly every group of rollouts informative.

 Finding 03

It transfers, and more than doubles task success.

On an independently built voice benchmark, with no further tuning: from last place to second.

 Finding 04

It fixes the failures it was built to expose.

Fewer unauthorised writes and dead loops, more recoveries, and fewer turns and tokens.
  • Audio-native.both sides talk in native speech, with no external ASR or TTS
  • Local.two open models on one machine, and no API bill
  • Trainable.the benchmark's own success check becomes the reward

The problem Measured, not trained

Voice agents could be measured. They could not be improved.

Training a voice agent takes three things at once: it must talk in speech, use tools over many turns, and learn from its own rollouts. Every earlier framework offers at most two.

Behind a proprietary voice API, no gradient crosses the boundary, and every rollout is billed.

The idea Change only the channel

Keep the benchmark. Let both sides speak.

A frozen open omni‑modal model plays the caller; the same model, trainable, plays the agent. Tasks, tools, database and success check come unchanged from τ²-bench, so speech is the only variable.

Schematic. Tool calls and their results stay text, so a wrong argument was misheard or mis-reasoned, never garbled on the way.

Both sides run locally, so the success check becomes a reward, and a rollout costs compute, not an API call.

How it works A reward for every tool call

Credit every tool call, and failing rollouts still teach.

GRPO learns from the differences inside a group of rollouts. When all of them fail the final check, an outcome-only reward scores them alike, and the group teaches nothing.

The paper's own example of four failing rollouts and their returns; the calls behind each return are drawn for illustration. Each executed tool call earns +0.1 and each failed call −0.1, and the benchmark's outcome is still added at the end.

What makes it affordable

Both models run locally

No API in the loop: a rollout costs local compute, and the training run costs $0 in API calls.

A faster rollout server

Serving both models with vLLM makes a training epoch 5.4× faster end to end.

Only a small adapter learns

A LoRA adapter on the agent's reasoning path. The speech path is left untouched.

The benchmark's own check still decides success. Per-turn credit only makes it dense enough to learn from.

The evidence Finding 01

Speech breaks hearing, not reasoning.

Same tasks, same tools, same check; only the channel differs. One misheard value sets off a cascade that ends the episode at zero.

Share of rollouts of the base 30B omni-modal model that show each failure; same tasks, tools and reward in both channels.

Three patterns in the speech rollouts

It mishears a slot value

Right tool, right argument slot, wrong value: a digit of a zip code, a character of an order ID, the spelling of a name.

It acts without authorisation

Pressed by an insistent caller, it makes a write it was not allowed to make, and ends the call believing it helped.

It loops

After an error it issues the identical call again instead of changing course, until the step budget runs out.

Audio agentic capability does not follow from audio understanding. It has to be trained.

The evidence Finding 02

The obstacle is sparsity, not signal.

At audio success rates almost every outcome-only group fails identically and carries no gradient. Crediting each tool call gives nearly every group something to learn from.

Training rollouts of the two reward settings on the same task suite, four rollouts per group. A group carries a gradient when its returns differ. Each square is 0.4% of groups.

Two rollouts that both fail still differ in how many calls they got right, and that difference is a gradient.

The evidence Finding 03

It transfers, and more than doubles task success.

The trained agent runs, with no further tuning, inside τ-Voice: a different user simulator, different voices over a telephone-grade line, and its own grader.

pass@1 under τ-Voice's own check, one attempt per task; 95% confidence intervals do not overlap in any domain. On the leaderboard, other systems are as reported by their providers; we did not train or re-run them.

The only thing that differs is the agent's weights.

The evidence Finding 04

It fixes the failures it was built to expose.

In the τ-Voice trajectories of both models, the failures SpeechGym exposes are the ones that move, while turns and tokens fall.

The same τ-Voice tasks, annotated for the base model and the trained model. Behaviour changes are in percentage points.

Repairs no one designed

It asks the caller to spell a name out.

It retries a lookup with the corrected spelling.

It switches lookup key when the first one fails.

Found in the annotated trajectories. The reward scores only task completion and tool-call success; it never mentions spelling, retries or lookup keys.

Success rises while turns and tokens fall: the opposite of gaming the reward.

Why it matters

The text-to-audio gap becomes something to optimise.

Until now that gap was an open measurement. A closed loop gives it an objective, a gradient and a stopping criterion.

What this opens up

Any open omni model drops in

The gym is a standard reset, step and reward loop. Nothing in it is tied to one model.

Text agent tasks can speak

Tasks, tools and checks carry over unchanged. A Banking domain with long numeric slots was added this way.

Safety you can measure

Unauthorised writes become a number that responds to training, and measuring them is the first step to controlling them.
