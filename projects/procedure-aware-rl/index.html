At a glance

The paper in four results.

What if a tool-using agent were rewarded for how it calls its tools, not only for which tools it calls? Score the order of its calls and the state they leave behind, and a 3B agent becomes a markedly better tool user.

Finding 01

It beats correctness-only RL.

On all three benchmarks, from the same 3B model and the same training data.

 Finding 02

It gains most where order matters.

Its multi-turn accuracy on BFCL-V3 nearly doubles over correctness-only RL.

 Finding 03

It learns the procedure.

It navigates before it creates, and recovers from a failed call instead of giving up.

 Finding 04

Both new rewards count.

Remove either one and accuracy drops, every time significantly.
  • Only the reward changes.standard GRPO, the same data, the same base model
  • No extra labels.rule-based rewards, read off the reference calls
  • Nearly free.a fraction of a second per training step

The problem

Correctness-only RL rewards tool calls as a bag of actions.

It matches each call’s tool name, parameter keys and values against the reference, and ignores their order. In a stateful environment, the order decides the result.

The paper’s sending-a-package example. Schematic.

A reward that cannot see the order cannot teach it.

The idea Reward the procedure

A correctness reward asks which calls were made. We also reward how.

Two terms join the reward: one for the order of the calls and the state they leave, one against malformed calls.

{% include proj/procedure-aware-rl/reward.html %}

Only the reward changes. The algorithm, the data and the model stay the same.

How it works

Near misses earn partial credit. Detours that end right still count.

Each call earns credit by how close it lands to its place in the reference order, and the first places weigh most. A second check asks only whether the rollout ends on the reference sequence, so a reasonable detour that still gets there is not punished.

{% include proj/procedure-aware-rl/order.html %}

The agent is told how close its procedure came, not just that it missed.

The evidence Finding 01

It beats correctness-only RL.

On all three benchmarks, including multi-hop search that lies outside its training data.

All three start from Qwen2.5-3B-Instruct; ToolRL is its released checkpoint, trained on the same data with format and correctness rewards only. BFCL-V3 and Bamboogle: mean over runs.

The same model, the same data, a different reward.

The evidence Finding 02

It gains most where order matters.

Multi-turn tasks chain calls through a changing state. That is where scoring the order pays off most.

Multi-turn at 3B: identical training data for all three. API-Bank Level 3 tests sequential tool coordination. At 7B: the released ToolRL-7B checkpoint against ours, three runs each.

Where the order decides the outcome, the procedural reward pays most.

The evidence Finding 03

It learns the procedure, not just the calls.

No rule in the reward says to navigate first or to retry after an error. Both emerge from scoring the sequence.

It learns the preconditions of its tools, and it treats an error as a reason to try another way.

The evidence Finding 04

Both new rewards count.

Remove either one and accuracy drops by more than two points. Remove both and the agent is back to correctness-only RL.

Every drop is significant under a paired bootstrap test on per-sample outcomes (p < 10−7).

Why NDCG to score the order

Same recipe; only the order metric changes. NDCG is the only one of the three that weighs early places more.

The procedural reward teaches when and in what order to call; the penalty teaches how to call correctly.

Why it matters

A 3B agent that holds its own against larger models.

On BFCL-V3 it posts the highest five-category average in the comparison, ahead of correctness-only RL and of larger models scored by the benchmark’s maintainers.

Larger models: official BFCL leaderboard scores, each under its own evaluation protocol. The 3B models: mean over runs.

What this opens up

Better agents from the same data

No extra labels, no larger teacher, no new algorithm. A better reward is enough.

Almost free to adopt

The new rewards are rules, not models: they add a fraction of a second to each training step.

The how, not only the what

Wherever the order of actions decides the outcome, the procedure itself can be rewarded.
